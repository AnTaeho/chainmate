# 앱으로 낼 때 기록은 어디에 남나 — 아이디어 (아직 만들지 않음)

사람이 물었다(2026-09-27): 「iOS나 맥 게임으로 배포했다고 치자. 그럼 전적은 어떻게 남는 거야?」

## 지금
- 기록 · 도감 · 해금 · 이어 하기 판이 전부 브라우저 `localStorage`에 있다(`src/ui/save.js`, `src/ui/records.js`).
- 브라우저 데이터를 지우거나 다른 기기에서 열면 처음부터.

## 1. 기기 안 저장 (앱의 기본)
- 맥(Tauri · Electron) · iOS(웹뷰로 감싸기) 앱에서는 지금 코드 그대로도 앱 안 저장소에 남아 껐다 켜도 이어진다.
- 앱을 지우면 같이 사라지고, iOS는 저장 공간이 모자랄 때 웹뷰 데이터를 정리할 수 있다.
- 그래서 앱으로 낼 때는 저장을 **앱 폴더의 파일**로 바꾼다. 저장 코드가 `save.js` · `records.js` 두 곳에 모여 있으니, 저장 · 불러오기 함수만 플랫폼별로 갈아 끼우는 얇은 층(웹 = localStorage, 앱 = 파일)을 둔다.
- 포장 절차는 `docs/PACKAGING.md`(Tauri)와 이어진다.

## 2. 플랫폼 동기화 (기기 사이 이어 하기)
| 플랫폼 | 저장 동기화 | 도전 과제 · 순위 |
|---|---|---|
| iOS · 맥 | iCloud(같은 Apple 계정이면 아이폰 ↔ 맥) | Game Center |
| 스팀 | Steam Cloud(저장 파일 자동 업로드) | 스팀 도전 과제 · 순위표 |

- 플랫폼끼리는 이어지지 않는다(아이폰 기록 ≠ 스팀 기록).
- 도전 과제는 이미 있는 해금 과제 · 도감 · 기록(`records.js`의 `UNLOCKS` 등)에서 옮긴다.

## 3. 우리 서버 (선택)
- 플랫폼을 넘는 이어 하기, 전 세계 순위표가 필요할 때. Vercel 함수 + 데이터베이스(Marketplace의 Postgres 등), 계정별 기록.
- **이 게임만의 장점: 결정성.** 같은 시드 + 같은 명령 = 같은 결과(규칙 층이 시드 rng · 명령 객체로만 움직인다). 그래서 「오늘의 대국」 순위표는 점수만 받지 않고 **명령 목록(둔 수)을 받아 서버가 `src/sim`을 그대로 다시 돌려 확인**한다. 조작한 점수는 다시 돌리면 맞지 않아 걸러진다.
- 명령 목록은 작다(한 판 수백 개 명령). 복기 기능(`docs/ideas/advisor.md`)도 같은 기록을 쓴다.

## 순서 제안
1. 앱으로 낼 때 저장을 파일로(저장 층 분리)
2. 플랫폼 기본 동기화(Apple: iCloud · Game Center, 스팀: Steam Cloud · 도전 과제)
3. 사람이 모이면 「오늘의 대국」 서버 순위표(둔 수 다시 돌려 확인)

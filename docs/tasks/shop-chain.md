## 판단 기준
1. **규칙은 `src/sim`에만 둔다.** 상태는 명령(`applyRun` · `apply`)으로만 바뀌고, 같은 시드와 같은 명령이면 결과가 같아야 한다. 봇과 화면은 같은 명령을 쓴다.
2. **오가도 공짜로 얻는 것이 없어야 한다.** 상점을 다시 열었을 때 진열이나 꾸러미가 새로 뽑히면 안 된다. 산 것 · 연 꾸러미 · 다시 진열 횟수 · 승급/빼기 사용 여부는 그대로 남는다.
3. **화면은 스스로 설명한다.** 조작 설명 문구를 넣지 않는다. 설명서 말투와 만든 쪽 용어는 쓰지 않는다. 「A가 아니라 B」 문장 꼴도 쓰지 않는다.
4. **판 봇은 돈에 민감하다.** 규칙이 바뀌면 짧은 하네스로 전후를 잰다(아래 검증).

## 할 일

### A. 관 선택 → 상점으로 돌아가기 (backlog 2)
**지금 흐름**
- 상점의 「다음 대국」(`src/ui/screens/shop.js`의 `leave`)을 누르면 `src/sim/run.js`의 `advance`가 불린다.
- `advance`는 `run.shop = null`로 상점을 지우고, 대국 칸을 올린 뒤 `phase = 'select'`로 넘긴다.
- 1 · 3 · 5관 첫 대국 앞에서는 `openDraft`가 불려 `draft` 단계가 먼저 온다.
- 관 선택 화면은 `src/ui/screens/select.js`다.

**할 일**
- **규칙**
  - 상점을 떠나도 그 상점 상태를 남겨 둔다. 예를 들어 `run.shop`을 지우지 않고, 다음 대국을 시작하는 `play`나 `skip`에서 지운다. 방식은 네 판단이다.
  - `select` 단계에 상점으로 돌아가는 명령(예: `{ type: 'shop' }`)을 더한다. 남은 상점이 있을 때만 된다.
  - 돌아가면 `phase = 'shop'`이 되고, 진열 · 꾸러미 · 횟수는 떠날 때 그대로다.
  - 다시 「다음 대국」을 누르면 관 선택으로 가고, 이미 올린 대국 칸은 다시 올리지 않는다.
  - 정석 고르기(`draft`)가 끼는 관에서는 정석을 고른 뒤의 관 선택에서만 상점으로 갈 수 있다. 정석을 두 번 고르거나 건너뛰는 틈이 생기면 안 된다.
  - 판의 첫 대국 앞처럼 남은 상점이 없으면 이 명령은 없다.
  - 건너뛰기(`skip`) 뒤에는 상점이 없다. 지금 흐름이 그렇다면 그대로 둔다(확인해서 보고서에 적는다).
- **저장**: 상태가 JSON 왕복에 안전해야 한다. 상점에서 저장하고 불러오는 기존 경로가 깨지지 않아야 한다.
- **화면**
  - 관 선택 화면에 상점으로 가는 단추를 둔다. 자리는 판 밖 틀이나 판 틀 규약을 따른다. 글은 짧게, 예를 들어 「상점」이다.
  - 남은 상점이 없으면 단추를 그리지 않는다.
  - 처음 안내(`coach.js` `hint`)는 넣지 않는다.
- **봇 · 도구**: `legalCommands`류와 `tools/shopbot.mjs` · `tools/run.mjs` 봇이 이 명령을 고르지 않게 한다. 오가기만 하는 명령이라 봇에게 의미가 없다.
- **테스트** (`test/`)
  - 상점 → 관 선택 → 상점 → 관 선택을 오가도 진열 · 꾸러미 · 돈 · 대국 칸이 그대로인가.
  - `play` 뒤에는 돌아갈 수 없는가.
  - 정석 관에서 정석을 두 번 고를 수 없는가.
  - 저장한 뒤 불러오는 왕복.
- **smoke**: 관 선택 → 상점 → 관 선택을 한 번 누르는 걸음을 더한다. 자리 규칙과 글 넘침 검사는 그대로 통과해야 한다.

### B. 사슬 중간에 목표를 넘겨도 사슬은 끝까지 (backlog 3)
**지금 코드**
- 규칙(`src/sim/battle.js` 사슬 끝 처리, 319행 근처 `if (b.target != null && b.score >= b.target) return finishBattle(...)`)은 사슬이 끝난 뒤에 승리를 판정한다.
- 사슬 점수가 목표에 더해지는 시점도 사슬 끝이다.
- 그런데 사람은 중간에 끝나 버린다고 느꼈다.

**할 일**
1. **먼저 재현한다.** 목표를 사슬 중간에 넘기는 판을 만들어 둘을 확인한다.
   - **규칙에서** 사슬이 이어지는지: 목표를 넘긴 뒤에도 `capture` 명령이 받아들여지는가.
   - **화면에서** 그렇게 보이는지: 목표 막대 · 승리 연출 · 입력 막힘이 사슬 도중에 일어나는가.
   - 화면 쪽은 `src/ui/screens/battle.js`에서 목표 막대(`goal` 구역)와 사슬 점수 미리 보기가 사슬 중에 막대를 채우는 연출, 대국 끝 연출이 도는 시점을 본다.
2. **원인에 맞게 고친다.**
   - 규칙이 끊는다면: 사슬이 끝날 때까지 판정하지 않게 한다.
   - 화면이 끝난 것처럼 보이게 한다면(막대가 꽉 차며 「이겼다」 느낌의 연출, 입력 막힘 등): 사슬 중에는 막대가 넘쳐도 계속 먹을 수 있게 보여야 한다.
     - 예: 막대가 목표를 넘어 ×2 · ×5 · ×10 눈금으로 계속 차오른다(기존 넘침 눈금을 쓴다). 승리 연출은 사슬이 끝난 뒤에만.
     - 모양은 네 판단이다. 새 설명 글은 넣지 않는다.
   - 사슬이 끝나면 곧바로 대국이 끝나야 한다(승리 연출 → 보상). 목표를 넘긴 채 다음 수를 두게 되면 안 된다.
   - 넘친 점수 덤(목표 ×2 · ×5 · ×10)은 사슬 끝의 최종 점수로 정해져야 한다.
3. **테스트**: 목표를 넘긴 뒤에도 같은 사슬에서 더 먹을 수 있고, 사슬이 끝나면 `won`이 되는지를 규칙 테스트로 확인한다.
4. **smoke**: 사슬 중 목표를 넘기는 장면에서 입력이 막히지 않는지 재는 검사를 가능하면 더한다(네 판단).
5. **전후 스크린샷**: 사슬 도중 목표를 넘긴 순간의 화면을 `docs/shots/shop-chain/`에 before · after로 남긴다. `tools/shots-layout.mjs` 식을 쓰면 되고, 직접 열어 확인한다.

## git · 함정
- 커밋은 갈래별로 나눈다: 규칙 / 화면 / 도구 / 테스트 / 문서.
- 메시지는 한국어로 「무엇을 했다 — 왜」.
- **`Co-Authored-By` 줄과 세션 링크를 넣지 않는다.**
- playwright가 전역에 없을 수 있다. 저장소 `node_modules`에 설치하지 마라. 필요하면 스크래치에 두고 `NPM_CONFIG_PREFIX`로 가리킨다.
- `tools/shots-layout.mjs --det` 두 벌을 동시에 돌리면 화소가 어긋난다. 한 벌씩 돌린다.
- 예상 밖의 변화가 생기면 스스로 우회하지 않는다. 테스트가 대량으로 깨지거나 명세와 부딪히면 그 항목만 멈추고 보고서에 선택지를 적는다.

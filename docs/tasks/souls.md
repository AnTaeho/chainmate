# 혼 등급 · 각성 지시서 (CHM-17)

클라우드 세션이 혼자 끝까지 한다. 중간에 답해 줄 사람이 없다. 결정은 네가 한다. 막히면 「판단 기준」으로 정하고 보고서에 「정한 것」으로 적은 뒤 계속한다.

**사용량이 떨어져 세션이 끊길 수 있다.** 아침에 같은 지시로 새 세션이 뜬다. 그래서:
- 커밋마다 푸시한다.
- 진행 기록을 꼭 남긴다.
- 새 세션은 진행 기록부터 읽고 이어 간다.

## 사람이 한 말 (2026-09-28 ~ 30)
- 「오늘 너프한 것들을 그냥 너프시키는 게 아니라 확률을 조절한다든가 하는 방식으로 조절하는 건 어떨까.」
- 「지금도 깨기 힘든데 단(레이팅)이 오르면 점점 더 어려워질 것 같다」 → 혼 너프는 되돌렸다(CHM-16).
- 설계 담당이 두 단계를 권했고, 사람이 받아들였다.
  - 1단계 혼 등급: 세기는 그대로 두고 만나는 확률과 값을 나눈다.
  - 2단계 각성: 중간~낮은 확률의 조각을 이어 모아 혼이 한 단계 더 세진다.

## 지금 상태 (코드에서 확인함)
- 혼은 16개다(`src/data/souls.js`).
- 상점(`src/sim/shop.js`)이 혼 열여섯을 **모두 같은 확률 · 같은 값 $4**로 낸다.
  - 107행: `SOULS[int(rng, SOULS.length)]`
  - 112행: 혼이 깃든 진열 기물 `soulOnPiece 0.12`
- 격언에는 등급(흔함 · 드묾 · 귀함 · 전설)이 있지만 혼에는 없다.

## 시작
0. `docs/tasks/souls-progress.md`가 있으면 먼저 읽고 이어 간다(한 줄 = 커밋 하나: 무엇 · 해시 · 다음 할 일). 없으면 만든다.
   - 브랜치는 `souls/1`로 한다. 환경이 막으면 허용되는 이름을 쓰고, 진행 기록 첫 줄에 적는다. 이어 가는 세션은 **그 브랜치를 체크아웃해서** 계속한다.
   - 커밋마다 푸시한다. main 푸시 · PR · amend · force-push는 하지 않는다.
   - 진행 기록 맨 위에 「지금 단계 · 다음 할 일」 한 줄을 늘 최신으로 둔다.
   - **이미 끝났으면(진행 기록에 「끝」, `docs/reports/souls.md`가 있음) 아무것도 하지 말고 끝낸다.**
1. 읽을 것:
   - 문서: `CLAUDE.md`, `docs/DESIGN.md`, `docs/HOOKS.md`(「불멸의 기보」 조각 사다리), `docs/design-notes/voice.md` · `layout.md` · `chess-terms.md`
   - 코드: `src/data/souls.js`, `src/sim/shop.js`, `src/data/maxims.js`(등급 · 가격 분포)
2. `npm test` · `npm run smoke` · `node tools/smoke.mjs --lang en`이 통과하는지부터 본다.

## 판단 기준
1. **세기는 깎지 않는다.** 등급과 각성은 만나는 확률과 사다리로 조절한다.
2. **뿌리 하나.** 각성 효과는 떨구기 · 먹기 · 갈아입기 · 지키는 적/끊김 · 프로모션 · 체크메이트 · 증원 가운데 하나를 키우거나 비튼다.
3. **드문 것은 조각을 이어 모아야 얻는다.** 한 번에 주지 않는다.
4. **난이도 과녁:** smart 단 0 판 승률 **40~50%**(지금 45% 근처), 단 8 10~15%. 등급을 넣은 뒤 이 범위를 벗어나면 등급 비율 · 값으로 맞춘다. 목표 곡선은 건드리지 않는다.
5. **하네스는 짧게** 돌린다(판 30~50개). 마지막 확인만 smart 100판 · 단 8 50판으로 한다.

## 1단계 · 혼 등급
- 혼 열여섯을 **흔함 · 드묾 · 귀함**으로 나눈다. 설계 담당의 첫안(바꿔도 된다):
  - 흔함: 굶주림 · 사냥꾼 · 역행 · 귀환 · 파문 · 사신
  - 드묾: 메아리 · 선봉 · 계주 · 결투 · 도약
  - 귀함: 순교자 · 잠행 · 초월 · 흡수 · 계승
- 나오는 확률은 등급 무게로 정한다. 예: 흔함 6 · 드묾 3 · 귀함 1. 혼이 깃든 진열 기물(`soulOnPiece`)에도 같은 무게를 쓴다.
- 값: 흔함 $4 · 드묾 $6 · 귀함 $9처럼 두되 하네스로 맞춘다.
- 화면: 혼 카드에 등급 빛깔을 두른다. 격언 등급 테와 같은 규칙이다. 도감 혼 탭에도 등급을 보인다.
- 각성을 빼고도 온전하게 끝나는 상태로 커밋하고, 진행 기록에 「1단계 끝」을 적는다.

## 2단계 · 각성
- **사다리:**
  - 혼이 깃든 기물로 사슬을 N번(예: 다섯) 이으면 그 기물에 「금이 간다」 표시가 붙는다. 기물에 남는다.
  - 금이 간 혼은 다음 가운데 하나로 **각성**한다:
    - 금빛 적을 먹고 대국을 이긴다
    - 마스터의 상자에서 세 칸 이상이 뜬다
    - 상점의 드문 두루마리 「깨우기」(값 비싸게, 드물게)
  - 조건과 확률은 네가 하네스로 정한다. 각성 혼이 판의 10~25%쯤에서 한 번 나오는 정도를 과녁으로 삼는다.
- **각성 효과:** 혼마다 하나씩, 16개를 만든다. 원래 규칙을 한 단계 키우거나 비튼다. 예:
  - 순교자: 끊길 때 둘레를 다 먹고 그 칸에서 한 번 더 잇는다
  - 초월: 아마존에서 한 단계 더
  - 흡수: 얻은 행마를 둘까지 쌓는다
  - 효과 글은 「조건: 효과」로 짧게 쓰고, 영어도 쓴다.
- **연출:** 금이 가는 순간과 각성하는 순간. 각성은 짧은 빛 · 소리 · 흔들림으로 하고, 한 수 연출 4초 규칙은 지킨다.
  - 각성 혼 카드 · 기물에는 금빛 테나 문양을 둔다.
  - 도감에 각성 칸을 둔다.
  - 처음 금이 갈 때 킹 말풍선으로 한 줄 안내한다.
- **봇 · 하네스:** 봇이 등급과 각성을 알고 산다. 하네스 출력에 「혼 등급별 산 판 · 각성한 판 · 그 판 승률」을 더한다.
- **시험:** 등급 확률이 결정적인지, 금이 가는 셈, 각성 조건 셋, 각성 효과 16개마다 규칙 시험 하나, 저장 왕복.

## 화면 · 글 규칙
- 레이아웃 규약을 지킨다: hug · 설명 자리 · 글 넘침 0 · 테에 붙음 0 · 누를 것 덮음 0.
- 용어는 체스 말(`chess-terms.md`)로 쓴다. 설명서 말투와 「A가 아니라 B」 꼴은 쓰지 않는다.
- 눈에 보이는 큰 변경(각성 표시 · 연출)은 구현 전에 시안 스크린샷 2~3개를 `docs/shots/souls/draft-*`로 남기고, 하나를 고른 까닭을 보고서에 적는다.

## 검증
- `npm test` 전부 통과.
- `npm run smoke`: SMOKE OK · 글 넘침 0 · 자리 규칙 어김 0 · 보류 0 · 한 수 연출 ×1 최대 4초 안.
- `node tools/smoke.mjs --lang en`: 옮기지 못한 글 0 · SMOKE OK.
- smoke에 각성 걸음을 넣는다(금이 감 → 각성).
- 전후 스크린샷을 `docs/shots/souls/`에 1배 + 3배로 남기고 직접 열어 본다.

## 알려진 함정
- playwright는 저장소 `node_modules`에 설치하지 않는다. 필요하면 스크래치에 두고 `NPM_CONFIG_PREFIX`로 가리킨다.
- 판 하네스는 판 하나가 길다(시계 때문). `--limit 400`을 쓴다.
- 커밋은 갈래별로 나눈다(규칙 / 수치 / 화면 / 글 / 도구 / 문서). 메시지는 한국어로 「무엇을 했다 — 왜」.
- **`Co-Authored-By` 줄과 세션 링크를 넣지 않는다.**
- 예상 밖의 변화가 생기면 그 항목만 멈추고, 선택지를 보고서에 적은 뒤 다음으로 간다.

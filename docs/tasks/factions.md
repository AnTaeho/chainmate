# 세력 지시서 — 관마다 다른 적

클라우드 세션에서 혼자 끝까지 한다. 중간에 답해 줄 사람이 없다. 결정은 네가 한다. 막히면 「판단 기준」으로 정해 보고서에 「정한 것」으로 적고 계속한다.

## 사람이 한 말 (2026-09-29)
「1관 연습대국부터 8관 명인 대국까지 컨텐츠는 똑같고, 달라지는 건 내 덱 파워뿐이라 결국 숫자놀이 하는 것 같다. 그렇다고 묘수풀이 방식으로 가자니 게임의 수명이 더 짧아질 것 같다.」
시안 네 가지(과제 · 세력 · 판 꼴 · 적의 차례) 가운데 **세력만** 넣기로 했다. 설계서는 **`docs/design-notes/factions.md`**다. 이 지시서는 설계서를 구현하는 절차다.

## 시작
0. `docs/tasks/factions-progress.md`가 있으면 먼저 읽고 이어서 한다(한 줄 = 커밋 하나: 무엇 · 해시 · 다음 할 일).
   - 브랜치는 `factions/1`이다. 환경이 막으면 허용되는 이름을 쓰고, 진행 기록 첫 줄에 그 이름을 적는다.
   - 커밋마다 푸시한다. main 푸시 · PR · amend · force-push는 하지 않는다.
1. 다음을 읽는다.
   - `CLAUDE.md`, `docs/DESIGN.md`, `docs/HOOKS.md`
   - `docs/design-notes/factions.md`(설계서), `voice.md`, `layout.md`, `board-tuning.md`(있으면)
   - `docs/reports/night2.md`(CHM-20 손질 절 포함)
   - 코드: `src/data/masters.js`, `src/sim/setup.js`(적 구성 · 특수 기물 · 특성 · 판 사물), `src/sim/run.js`(관 · 명인 · 단 표), `src/ui/screens/select.js`, `battle.js`, `codex.js`
2. 먼저 통과를 확인한다: `npm test`, `npm run smoke`, `node tools/smoke.mjs --lang en`.

## 판단 기준
1. **퍼즐의 모양이 달라야 한다.** 세력은 적 구성 · 판 사물 · 규칙으로 「무엇을 입고 어떤 길로 잇는가」를 바꾼다. 숫자(목표 · 무게)만 바꾸는 세력은 실패다.
2. **뿌리 하나.** 버릇 · 우두머리는 떨구기 · 먹기 · 갈아입기 · 지키는 적/끊김 · 승급 · 외통 · 증원을 비튼다. 옛 명인 규칙을 되살려 쓰고, 새 규칙을 만들어야 한다면 이 동사 안에서만 만든다.
3. **세력끼리 공평하게.** 같은 관 기준으로 명인 통과율이 세력마다 ±15%p 안에 들어야 한다.
4. **판 운 설계는 지킨다.** 시계 · 다시 놓기 · 거르기(`BOARD_TUNING`)는 그대로 쓰고, 설정 한 곳에서 켜고 끄는 구조를 깨지 않는다.
5. **판 봇은 돈과 목숨에 민감하다.** 규칙을 바꾸면 하네스로 잰다.

## 할 일
1. **데이터 · 규칙**: 설계서 표대로 `src/data/factions.js` 여덟을 만든다(주력 적 가중치 · 고유 적 · 버릇 · 우두머리).
   - 버릇 · 우두머리는 `scoring.js` 조정자 훅과 대국 규칙 깃발로 넣는다. 규칙 코드에 id별 분기를 넣지 않는다. 새 훅이 필요하면 일반형으로 만든다.
   - 옛 명인 여덟은 세력의 우두머리로 옮긴다. 옛 저장(명인 id)을 새 구조로 옮기는 길을 둔다.
   - 적 구성: 관별 무게 곡선(`enemyWeights`)에 세력 가중치를 곱하는 식이다(방법은 네 판단). 특수 기물이 4관부터 나오는 규칙은 세력의 고유 적만 1관부터 조금 나오게 바꾼다.
2. **판(런)**: 1관 농민군, 8관 왕궁 근위로 고정하고, 2~7관은 판 시드로 섞는다. `run.factions` 같은 필드로 JSON 왕복이 안전해야 한다.
   - 단 표에서 명인 「대가」를 가리키던 항목(예: 대가 목표 ×1.25)은 왕궁 근위의 우두머리로 옮긴다.
3. **봇 · 하네스**: 봇이 세력 규칙 아래서 두게 한다. 하네스 출력에 세력별 대국 통과율(연습 · 정식 · 명인)과 **관별 「가장 많이 입은 모습」 분포**를 더한다.
4. **화면**(설계서 「화면」 절). 구현 전에 시안 2~3개를 `docs/shots/factions/draft-*`로 찍고, 하나를 골라 버린 안과 함께 보고서에 적는다.
   - 관 선택: 세력 문장 · 이름 · 버릇 한 줄, 명인 카드의 우두머리 이름과 규칙, 판의 길에 다음 관 세력 문장.
   - 대국: 머리 칸 「농민군 · 연습 대국」, 세력마다 판 틀이나 바닥 무늬 한 가지.
   - 세력 문장 여덟(12×12 도트).
   - 처음 안내: 새 세력을 처음 만날 때 한 줄.
   - 도감 세력 탭.
   - 영어 글 · 낱말 풀이.
   - 레이아웃 규약을 지킨다(hug · 설명 자리 · 글 넘침 0 · 테에 붙음 0).
5. **글**: voice.md를 따른다(「조건: 효과」, 짧게). 설명서 말투와 「A가 아니라 B」 꼴은 쓰지 않는다.
6. **시험**: 세력 섞기가 결정적인지, 버릇 · 우두머리마다 규칙이 맞는지, 옛 저장을 옮기는 길을 시험한다.

## 재기와 맞추기 (짧게, 마지막만 길게)
- 판 하네스는 한 번에 30~50판으로 돌리고, 마지막 확인은 smart 단 0 100판 · 단 8 50판 · none · random 50판씩 돌린다. 판 운은 `tools/luck.mjs --runs 30 --k 20 --sk 10`으로 한 번 잰다.
- 과녁은 셋이다.
  - 판 승률: CHM-20 뒤 값을 유지한다(단 0 smart 50% 안쪽, 단 8 10~15%).
  - 세력별 명인 통과율: 같은 관 기준 ±15%p 안.
  - 관별 「가장 많이 입은 모습」: 세력마다 달라야 한다(기병대 → 나이트 몫이 가장 큼 등).
- 벗어나면 세력의 버릇 · 구성을 조정한다. 목표 곡선은 마지막 수단이다.

- `npm test` 전부 통과.

- 스크린샷: `docs/shots/factions/`에 세력 여덟의 관 선택 · 대국 첫 화면을 한국어로, 대표 셋은 영어로도 찍는다. 1배와 3배 모두, 직접 열어 본다.

## 알려진 함정
- playwright는 저장소 `node_modules`에 설치하지 않는다. 필요하면 스크래치에 두고 `NPM_CONFIG_PREFIX`로 가리킨다.
- `--det` 스크린샷 두 벌을 동시에 돌리면 화소가 어긋난다.
- 판 하네스는 판 하나가 길다(시계). `--limit 400`을 쓰고, 비교는 같은 조건에서 한다.
- 커밋은 갈래별로 나눈다(규칙 / 수치 / 화면 / 글 / 도구 / 문서). 메시지는 한국어로 「무엇을 했다 — 왜」.
- **`Co-Authored-By` 줄과 세션 링크를 넣지 않는다.**
- 예상 밖의 변화(테스트 대량 실패, 설계와 부딪힘)가 생기면 그 항목만 멈추고, 선택지를 보고서에 적은 뒤 다음으로 간다.

# 밤샘 지시서 — 화면 · 연출 · 판 밖 · 다듬기

이 파일 하나로 몇 시간 동안 혼자 일한다. 중간에 대답해 줄 사람이 없다. 막히면 멈추지 말고, 아래 「판단 기준」으로 정해서 기록하고 다음으로 간다.

## 0. 시작할 때 (매번)

1. `CLAUDE.md`, `docs/DESIGN.md`, `docs/HOOKS.md`, `docs/reports/2b.md`, `docs/mockup.html`을 읽는다. 규칙·말투·git 규칙은 CLAUDE.md가 우선이다.
2. **`docs/tasks/night-progress.md`가 있으면 먼저 읽고 거기서 이어 간다.** 없으면 만든다. 이 파일은 다음 세션이 이어받는 유일한 기억이다.
3. 브랜치: `night/1`이 원격에 있으면 받아서 이어 가고, 없으면 `main`에서 만든다. **main에는 푸시하지 않는다. PR을 열지 않는다. amend·force-push 금지.**
4. `npm test`가 전부 통과하는지 먼저 확인한다. 실패하면 그것부터 고친다(버그 커밋).

## 1. 일하는 리듬

- 작업 하나(= 커밋 하나)를 끝낼 때마다: `npm test` 통과 → 커밋 → **`git push origin night/1`** → `night-progress.md`에 한 줄 추가(무엇을, 커밋 해시, 다음 할 일) 후 같이 커밋. 세션이 언제 끊겨도 잃는 게 없게.
- 한 단계(A·B·C)가 끝나면 `docs/reports/night-<단계>.md`에 보고서를 쓰고 커밋·푸시한 뒤, **기다리지 말고 다음 단계로 간다.**
- 모든 단계가 끝나면 D(다듬기 목록)를 위에서부터 계속한다. 목록이 비거나 막힐 때만 멈춘다.
- 마지막(또는 멈출 때) `docs/reports/night.md`에 전체 요약: 바뀐 것, 지금 할 수 있는 것(「이렇게 열어서 이렇게 논다」), 알려진 문제, 남은 목록.
- 컨텍스트가 길어지면 자동으로 요약된다. 요약 뒤에는 `night-progress.md`를 다시 읽고 이어 간다.

## 2. 판단 기준 (묻지 않고 정할 때)

1. 뿌리: **잡으면 그것이 된다.** 떨구기·먹기·갈아입기·응수/끊김·승급·외통이 화면에서 가장 잘 느껴지는 쪽.
2. 도파민: 숫자가 부푸는 과정을 보여 주고, 드문 순간은 크게 축하한다(HOOKS.md 「의식」).
3. 읽기 쉬움: 480×270 도트에서 한눈에 구별되는 쪽.
4. 규칙(`src/sim`, `src/data`)은 **버그가 아니면 바꾸지 않는다.** 화면을 위해 이벤트·조회 함수를 더하는 건 괜찮다(하네스 수치가 그대로인지 `node tools/sim.mjs --battles 300 --seed 1`로 확인).
5. 정한 것은 보고서 「내가 정한 것」에 한 줄씩, 버린 대안과 이유도 한 줄.

## 3. 화면 글 규칙 (어기면 고친다)

- UI 흐름 중간에 조작법 설명 문구 금지. 컨트롤이 스스로 설명하게(떨굴 수 있는 칸이 빛나고, 먹을 수 있는 적이 흔들린다).
- 설명서 말투, 만든 쪽 용어(엔진, 시뮬, 스폰, 틱, 버프, 트리거, 쿨다운, 팩, 이벤트…) 금지. DESIGN.md 「세계의 말」만.
- 「A가 아니라 B」 문장 꼴 금지.
- 격언·명인 설명은 `src/data`의 짧은 효과 문구를 그대로 쓴다.

## 4. 검증 방법 (클라우드에 화면이 없다)

- **규칙 테스트**: `npm test`.
- **화면 연기 시험** `tools/smoke.mjs` (A-1에서 만든다): 가짜 캔버스 컨텍스트(그리기 호출을 세기만 함)와 가짜 입력으로, 실제 `src/main.js`의 화면 흐름을 봇 명령으로 한 판 끝까지(타이틀 → 대국 → 상점 → … → 결과) 돌린다. 예외 0, 모든 화면 방문, 프레임당 그리기 시간 기록. 새 화면을 만들 때마다 여기에 넣는다. `npm run smoke`로 돈다.
- **스크린샷(되면)**: `npx -y playwright@latest install --with-deps chromium`이 되면 `tools/shots.mjs`로 화면별 PNG를 `docs/shots/`에 저장한다(480×270 원본 + 3배 확대). 설치가 안 되면 건너뛰고 보고서에 적는다. 스크린샷은 저장소에 커밋한다(각 50KB 안팎).
- **하네스는 느리다**(클라우드 코어 4개, smart 300판 ≈ 20~30분, 전설이 겹친 판 하나가 수십 분 붙잡기도 한다). 수치를 고치며 볼 때는 `--runs 100`, 확정할 때만 300판 한 번. 같은 수치로 두 번 돌리지 않는다. 판 하네스는 백그라운드로 돌리고 그동안 다른 일을 한다.
- 눈에 보이는 결정은 `docs/shots/README.md`에 「정한 안 / 버린 안 / 이유」로 남긴다(시안 규칙).

## A. 화면 (가장 중요 — 사람이 처음으로 직접 해 보는 판)

목표: 브라우저에서 `npm run serve` → `http://localhost:8000`을 열면 타이틀부터 8관 명인까지 끝까지 할 수 있다.

### A-1 뼈대
- `index.html`, `style.css`, `src/main.js`, `src/render/`, `src/ui/`(입력·화면 상태), `tools/smoke.mjs`, `package.json`에 `"smoke"` 스크립트.
- 내부 해상도 480×270 캔버스, 창에 맞춰 정수배 확대(작으면 비정수 허용) + 레터박스, `image-rendering: pixelated`, 배경은 펠트 색.
- 마우스 좌표 → 게임 좌표 변환(`getBoundingClientRect`, DPR, 레터박스 포함).
- 루프: `requestAnimationFrame`, 연출은 시간 기반. sim은 명령이 들어올 때만 진행(턴제).
- **글자**: Galmuri11(`assets/fonts`, 이미 있음)을 `document.fonts.load`로 기다린 뒤, 오프스크린 캔버스에 12px로 그리고 **알파를 문턱값(>0.5)으로 잘라** 도트처럼 또렷하게 캐시한다. 숫자는 굵게(Bold 파일).
- **스프라이트**: mockup의 `SPR`·`TONE`·`sprite()`를 `src/render/sprites.js`로 옮긴다(16×22, 칸 28px, 테두리·명암 자동). 한 번 그려 오프스크린 캔버스에 캐시.
- 색은 mockup `PAL`에서 시작.

### A-2 대국 화면 (mockup 배치 그대로)
- 가운데 8×8 판(칸 28, 판 224px), 왼쪽 판(관·대국 종류, 목표, 점수, 값 × 연쇄 상자, 사슬 모습 줄, 수·무르기 구슬, 상금, 주머니), 오른쪽(격언 칸, 손).
- 흐름:
  1. 손의 기물을 누르면 들어 올려지고, 떨굴 수 있는 칸이 은은하게 빛난다. 다른 칸을 누르면 내려놓는다.
  2. 칸을 누르면 떨군다. 이제 먹을 수 있는 적이 살짝 떠오른다(위아래 1px 흔들림).
  3. 적을 누르면 먹는다: 기물이 미끄러져 가고(0.12초), 적이 도트 조각으로 부서지고, 내 기물이 새 모습으로 뒤집힌다(가로 1→0→1, 0.1초). 값·연쇄 숫자가 튀어 오른다.
  4. 응수가 걸리면 노림수 칸이 붉게 깜빡이고, 먹을 수 있는 노림수만 떠오른다.
  5. 끊김: 짧은 정지(0.15초), 붉은 금, 기물이 되잡혀 사라진다.
  6. 사슬이 끝나면 값 × 연쇄가 가운데로 모여 곱이 터지고, 점수가 누적에 흘러 들어간다(숫자가 빠르게 올라가는 카운트).
  7. 목표를 넘기면 대국 승리 화면으로.
- 무르기: 손 기물을 여럿 고른 뒤 무르기 버튼(아이콘 + 「무르기」 글자). 수 구슬·무르기 구슬이 줄어드는 게 보인다.
- 증원 그림자: 다음에 들어올 칸에 흐린 적 + 점선 테두리.
- 안개(명인): 가려진 칸은 짙은 무늬.
- 황금 기물: 금빛 테두리가 반짝인다.
- 사슬 평가(!, !!, !!!, ∞)와 목표 초과(×2, ×5, ×10)는 2b 이벤트를 받아 표시(B에서 크게 키운다. A에서는 글자만).
- 키보드: 1~5 손 선택, Esc 취소·일시정지, Space 무르기 확정, Enter 다음. 화면에 키 설명은 쓰지 않는다.
- 되돌리기 없음(사슬 한 칸씩 확정).

### A-3 판 흐름 화면
- **타이틀**: 게임 이름 「체인메이트」(큰 도트 글자), 새 판 · 이어 하기(저장 있을 때) · 설정. 뒤에 기물들이 천천히 떨어지며 갈아입는 짧은 애니메이션.
- **관 선택**: 연습 · 정식 · 명인 세 장. 목표 점수, 보상, 명인 규칙, 건너뛰기 보상(패). 「두기」 / 「건너뛰기」.
- **대국 승리**: 보상이 한 줄씩(기본 · 남은 수 · 적립 · 외통 · 넘친 목표) 동전 소리와 함께 쌓인다(A에서는 소리 없이 순서만).
- **상점**: 진열 2 + 꾸러미 2 + 다시 진열 + 나가기. 카드 위에 올리면 설명 말풍선. 격언 칸(끌어서 순서 바꾸기, 팔기), 소모품 칸(누르면 대상 고르기), 주머니 보기(기물 승급·버리기).
- **꾸러미 열기**: 3장이 뒤집히며 나오고 하나 고르기(건너뛰기 가능). 금빛 꾸러미는 금빛.
- **명인의 상자**: 2b 이벤트의 릴 순서대로 칸이 돌고 멈춘다(A에서는 단순 순서 표시, B에서 슬롯 연출).
- **불멸의 기보**: 조각 획득 알림, 격언 칸 옆 명국 조각 표시(모은 수/3), 재현 조건은 첫 조각을 가진 뒤에만 보인다. 전설 완성 장면(B에서 크게).
- **판 결과**: 이김/짐, 도달 관, 최고 한 수, 목표에 모자란 점수(아슬아슬), 모은 조각. 「다시」 / 「타이틀」.
- **일시정지**: 계속 · 설정 · 타이틀로.
- 모든 화면을 smoke에 넣는다.

### A-4 저장
- `localStorage`에 판 상태(JSON) 자동 저장: 대국 시작, 수 끝, 상점 행동마다. 이어 하기로 복원. try/catch로 감싸고 저장 실패해도 게임은 돈다.
- 설정(소리 크기, 연출 속도 ×1/×2/×4, 화면 흔들림 끄기) 저장.

### A 끝 조건
smoke 통과, `npm test` 통과, (되면) 화면별 스크린샷, `docs/reports/night-A.md`.

## B. 연출과 소리 (HOOKS.md 「의식」 표 전부)

- **먹기**: 부서지는 도트 조각(8~16개, 중력), 칸 번쩍, 음 높이 한 칸 위(사슬 길이만큼 음계 상승, 도-레-미… 한 옥타브 넘으면 다음 옥타브).
- **갈아입기**: 뒤집힘 + 은빛 반짝, 짧은 「촥」.
- **사슬 평가**: ! · !! · !!! · ∞ 글자가 판 위에 쾅 찍힘. 단계마다 판 테두리 불빛(흰 → 금 → 붉은 금 → 무지개)과 화면 흔들림(1 · 2 · 3 · 4px, 설정으로 끄기).
- **끊김**: 히트스톱, 붉은 금, 낮은 둔탁음. 아프지만 짧게.
- **승급**: 폰이 금빛으로 솟으며 퀸, 종소리.
- **외통**: 킹이 천천히 쓰러짐, 전체 정지 0.5초, 큰 글자 「외통」.
- **점수 합산**: 값 상자와 연쇄 상자가 가운데로 모여 부딪혀 곱이 터짐. 누적 점수가 목표를 넘는 순간 숫자에 불이 붙음. 넘친 비율(×2 · ×5 · ×10)마다 더 크게.
- **대국 승리 보상**: 한 줄마다 동전 소리 하나씩.
- **명인의 상자**: 슬롯 릴. 칸마다 딸깍 멈춤, 3개면 반짝, 5개면 화면 전체 금빛 + 팡파르.
- **황금 기물 먹기**: 금가루 폭발, 높은 방울 소리.
- **조각 획득 · 전설 완성**: 조각이 격언 칸으로 날아감. 전설 완성은 화면 정지 → 그 명국의 마지막 수를 판 위에 재생(2~3수, 상징적으로) → 금박 격언이 떨어져 6번째 칸에 박힘 + 전용 한 소절.
- **판본**: 은박(가로로 흐르는 빛), 자개(무지갯빛 얼룩), 무지개(색 순환), 흑요(검은 광택 + 보랏빛 테).
- **소리**: WebAudio 합성만(파일 없음). `src/audio/`. 첫 클릭 전에는 소리를 켜지 않는다(브라우저 규칙). 효과음 + 배경 음악(대국: 차분한 저음 반복, 사슬이 길어질수록 층이 하나씩 더해짐; 상점: 가벼운 반복; 명인: 긴장). 소리 크기 설정.
- 연출 속도 설정(×1/×2/×4)이 모든 연출에 먹는다. `prefers-reduced-motion`이면 흔들림 끔.
- smoke에 연출 시간 합이 과하지 않은지(한 수 연출 ≤ 4초 at ×1) 검사 추가.

### B 끝 조건
smoke·테스트 통과, 스크린샷(되면), `docs/reports/night-B.md`.

## C. 판 밖 (DESIGN.md 「판 밖에 남는 것」)

- **기록**: 판 수, 이긴 판, 최고 관, 최고 한 수(점수와 그 사슬의 모습 줄), 외통 수, 전설 완성 수.
- **도감**: 격언 · 명인 · 명국 · 오프닝 · 판본. 본 것만 채워지고 나머지는 「?」. 명국은 조각 수까지.
- **오프닝 해금**: DESIGN.md의 기본 / 런던 / 시실리안 / 퀸스 갬빗 / 룩 엔딩(`src/data/openings.js`를 채운다 — 규칙 층 변경이므로 테스트 추가, 하네스로 오프닝별 승률을 재서 보고서에). 해금 조건은 과제(예: 외통 10번, 5관 도달, 전설 1번 완성 …) — 네 판단으로 정하고 결과 화면에 「다음 해금까지」를 하나 보여 준다.
- **단 1~8**: 한 판 이기면 다음 단. 단마다 규칙 하나 누적(목표 ×1.25, 증원 +1, 상점 가격 +1, 무르기 −1, 명인 상자 5개 확률 반, 조각 확률 반, 수 −1, 대가 목표 ×1.5). 규칙 층에 넣고 테스트·하네스(단 1·4·8 smart 100판씩).
- **오늘의 대국**: 날짜 시드. 같은 날엔 모두 같은 판. 오늘의 최고 기록 따로.
- 타이틀에 도감 · 기록 버튼. 결과 화면에 새로 채워진 도감 칸 · 해금 알림.

### C 끝 조건
테스트·smoke 통과, 하네스 원문, `docs/reports/night-C.md`.

## D. 다듬기 목록 (위에서부터, 시간이 남는 만큼)

0. 2b 확정 수치(`docs/reports/2b.md`): smart 판 승률 24.3%(목표 10~20% 조금 위), 판이 막힘으로 끝나는 비율 5.7%, 명국 「세기의 대국」 첫 조각이 300판에서 한 번도 안 나왔다(나오는 곳 = 기보 꾸러미 — 봇이 기보 꾸러미를 거의 안 여는 탓인지, 규칙 버그인지 먼저 가린다).
1. 명인 1~7이 너무 약하다(통과 90~97%). 각 명인이 떨구기·먹기·갈아입기·응수 중 하나를 확실히 비틀게 규칙을 세게 하고, 하네스로 명인 통과율 75~85%에 맞춘다. 이걸로 판 승률도 10~20% 안으로 내려오게 한다.
2. 상점 봇이 정보·돈 격언과 건너뛰기를 안 쓴다 — 봇에 가치 추정을 더해 그 격언들의 실제 가치를 잰다. 쓸모없으면 효과를 올린다.
3. 첫 판 흐름: 첫 대국은 목표가 낮고 판이 단순해서 첫 사슬이 10초 안에 나오게(1관 연습 판 생성에 「쉬운 사슬 하나 보장」).
4. 손맛 점검: 한 수 연출 총 시간, 클릭 반응(입력 → 첫 반응 ≤ 50ms), 60fps 유지(smoke 프레임 시간).
5. 말풍선·설명 글 전수 검사(화면 글 규칙).
6. 격언 32종 각각 아이콘(12×12 도트, 코드로 그림).
7. 명인 8명 초상(32×32 도트, 코드로 그림)과 등장 연출.
8. 격언 추가 8종(뿌리에 꿰이는 것만, 테스트·하네스 포함).
9. 끝없는 대국 화면·기록.
10. 접근성: 색각 이상 대비(노림수 붉은색에 무늬 더하기), 글자 크기 옵션(×2 배율 UI).
11. 영어 문구 표(`src/data/i18n/`) — 화면 문구를 키로 빼고 영어 번역 추가, 설정에서 언어 선택.
12. 성능: 전설 조합에서 풀이기가 느려지는 경우(2b 보고서 참고) — 화면의 「떨굴 칸 표시」가 느려지지 않게 캐시.
13. 데스크톱 포장 준비 문서(`docs/PACKAGING.md`): Tauri로 감싸는 절차, 저장 위치, 창 크기 — 실제 설치는 하지 않는다.
